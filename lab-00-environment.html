Lab 0: Environment setup

Time: ~1 h · Cost: $0 · Used by: every later lab Outcome: a working workstation with a local model, a Python/Node toolchain, containers, and (optionally) a Kubernetes cluster, all behind one repo layout.

0.1 Hardware check

Your machine What to run locally
≥ 16 GB RAM (or Apple Silicon ≥ 16 GB) 7–8B model, 4-bit quantized (~5 GB)
8–12 GB RAM 3–4B model (qwen3:4b, llama3.2:3b)
< 8 GB RAM Skip local models; use a free hosted tier (see 0.5)

No GPU required. Without one, generation is slower (expect a few tokens/s on CPU), which is fine for these labs.

0.2 Core tooling

# Python package/project manager (fast, replaces pip+venv for our purposes)
curl -LsSf https://astral.sh/uv/install.sh | sh

# Containers (Fedora/RHEL). On macOS: brew install podman
sudo dnf install -y podman git

# Node 20+ (needed for TypeScript MCP servers and MCP Inspector)
# Fedora/RHEL:
sudo dnf install -y nodejs npm
# or use nvm: https://github.com/nvm-sh/nvm

# Verify
uv --version && podman --version && git --version && node --version && python3 --version

Python 3.11+ is needed. uv can install and manage it for you: uv python install 3.12.

0.3 Local model runtime (Ollama)

# Linux/macOS installer (or download the app from ollama.com)
curl -fsSL https://ollama.com/install.sh | sh

# Pull one model that supports tool calling (needed from Chapter 3)
ollama pull qwen3:8b        # or qwen3:4b / llama3.2:3b for smaller machines

# Test interactively, then exit with /bye
ollama run qwen3:8b "Say hello in one sentence."

# Test the OpenAI-compatible API (this is what all our labs use)
curl -s http://localhost:11434/v1/models | head -c 300

Note on "thinking" models: Qwen3 and other reasoning models emit hidden/visible "thinking" tokens. They improve answers but inflate token counts and latency. You'll observe this in Lab 1.

Red Hat-flavored alternative (do later, in Lab 15b): RamaLama or Podman AI Lab serve models in containers with the same OpenAI-compatible API. For now Ollama is the simplest start.

0.4 Repo layout

mkdir -p ~/agentic-labs && cd ~/agentic-labs
git init

Never commit .env. It holds API keys.

0.5 Hosted model backup (free tier) and spend controls

Pick one provider for comparisons. All expose an OpenAI-compatible endpoint:

Provider Base URL Notes
Google AI Studio (Gemini) https://generativelanguage.googleapis.com/v1beta/openai/ Generous free tier, rate-limited
Groq https://api.groq.com/openai/v1 Free tier, very fast open-weight models
OpenRouter https://openrouter.ai/api/v1 Has :free models; good for trying many models
GitHub Models https://models.github.ai/inference Free with a GitHub account, rate-limited

Free tiers, model names and limits change often. Check each provider's current docs.

If you ever add a paid key:

  1. Create a separate API key per project (easy to revoke).
  2. Set a monthly spend limit / budget alert in the provider console before the first call.
  3. Use small/cheap models for labs; save the big models for capstone comparisons.
  4. Keep a costs.md log (date, lab, spend). Total target for the whole path: under ~$15.

0.6 Kubernetes / OpenShift access

Superseded for cluster-based labs: if you use disposable OpenShift clusters (recommended for Labs 9, 14 and 15), use the lab-env/ toolkit instead of the manual steps below: see lab-env/README.md. The kind and Developer Sandbox notes below remain a free fallback.

Needed from Lab 9 onward. Do it now if you have time, otherwise defer.

# Local cluster with kind (needs podman or docker)
# Install: https://kind.sigs.k8s.io/docs/user/quick-start/
kind create cluster --name agentic
kubectl cluster-info --context kind-agentic

For Podman as the kind provider: KIND_EXPERIMENTAL_PROVIDER=podman kind create cluster (rootless setups may need extra cgroup configuration; see kind docs).

Red Hat Developer Sandbox (free OpenShift): sign up at https://developers.redhat.com/developer-sandbox with a free Red Hat account. Note the resource limits and time-limited lifecycle; check current terms. Install oc from the console's "Command line tools" page.

0.7 Verification checklist

Run each line; all should succeed.

uv --version
python3 --version           # 3.11+
node --version              # 20+
podman run --rm quay.io/podman/hello    # container runtime works
ollama list                 # shows your model
curl -s http://localhost:11434/v1/models >/dev/null && echo "LLM API OK"
git status                  # inside ~/agentic-labs

Optional: kubectl get nodes (kind) or oc whoami (Sandbox).

0.8 Troubleshooting

Symptom Fix
Ollama model is very slow / machine swaps Use a smaller model (qwen3:4b, llama3.2:3b)
connection refused on port 11434 Start the server: ollama serve (or launch the app)
Podman rootless errors Check podman info; on RHEL/Fedora ensure subuid/subgid are set for your user
uv not found after install Restart shell or source ~/.bashrc
Corporate proxy blocks downloads Set HTTPS_PROXY; for local calls set NO_PROXY=localhost,127.0.0.1
