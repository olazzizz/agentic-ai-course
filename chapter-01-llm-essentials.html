Lesson 1.1: How LLMs behave

Core ideas

Tokens. Models read and write tokens (sub-word chunks), not words. Rule of thumb for English: 1 token ≈ 4 characters ≈ ¾ of a word. Other languages, code and JSON are usually less efficient (more tokens per word), and this matters for cost and context budget.

Next-token prediction. An LLM produces text one token at a time, each chosen from a probability distribution conditioned on everything before it. There is no built-in fact database or "truth check": fluent output and correct output are different things.

Context window. The maximum tokens (input + output) the model can consider in one request. It is the model's entire working memory; anything not in the window doesn't exist for the model. Long windows are not free: cost and latency grow with length, and models can under-use information buried in the middle of very long contexts.

Sampling. Temperature controls randomness. Low values give more consistent output; high values give more variety. Even at temperature 0, output is not guaranteed identical across runs (batching, hardware and provider changes can alter results). Design for tolerance, don't assume determinism.

Hallucination. Confident but wrong or invented output. It is a property to manage (grounding via retrieval, citations, verification steps, constrained outputs, human review), not a bug that will vanish.

Prompt = program. System prompt, instructions, examples and retrieved data together are the "code" you ship. They need version control, tests and review like any other code.

Reasoning models spend extra "thinking" tokens before answering. They're better at multi-step problems but slower and costlier per answer, and you're billed for thinking tokens on most providers.

Architect's lens

  • Anything a model must know must be in the context (or reachable via a tool). This single fact motivates RAG, memory and MCP.
  • Non-determinism means you need evaluation sets, not one-off manual testing (Chapter 11).
  • Treat the prompt as a versioned artifact.

Lesson 1.2: The model landscape and how to choose

Categories

Category Examples of what to expect Typical strengths Typical trade-offs
Frontier closed (API) Top models from Anthropic, OpenAI, Google Best quality, tool use, long context, managed Data leaves your boundary, per-token cost, vendor dependence
Open-weight large Llama, Qwen, Mistral, DeepSeek, gpt-oss families Run anywhere, customizable, no per-token fee Need GPUs/ops, licence terms vary, may trail frontier
Small models (SLMs, 1–14B) Granite, Qwen small sizes, Phi, Gemma Cheap, fast, edge/on-prem friendly, good for narrow tasks Weaker at complex reasoning and long tool chains
Reasoning-tuned Available in all of the above Multi-step problem solving Latency and token cost
Multimodal Text + image (+ audio/video) Documents, screenshots, charts Higher cost, varying quality

Names and rankings change quarterly. Check current leaderboards and vendor docs rather than memorizing a list.

Selection criteria (use as a checklist with customers)

  1. Task quality on their data (test, don't trust benchmarks).
  2. Tool-calling reliability (critical for agents; see Chapter 3).
  3. Latency (time-to-first-token and tokens/s) versus user expectations.
  4. Cost per task, not per token.
  5. Context length actually needed.
  6. Data residency, privacy and licence (can data leave? can weights be self-hosted? commercial use allowed?).
  7. Operational fit: managed API vs self-hosted; GPU availability; skills.
  8. Lock-in risk: OpenAI-compatible APIs and gateways reduce it.

Architect's lens

  • Multi-model is normal: small model for routing/classification/extraction, larger model for hard reasoning ("model routing").
  • Models are a replaceable component. Architect for swap-ability (API abstraction, eval suite to re-validate).

Lesson 1.3: Prompting, structured output, RAG or fine-tuning?

Structured outputs

Free-form text is hard for software to consume. Options, from weakest to strongest guarantee:

  1. Prompt-only ("reply in JSON"): often works, sometimes wraps in code fences or adds prose. Fragile.
  2. JSON mode: output is valid JSON, but not necessarily your schema.
  3. Schema-constrained output (response_format with JSON Schema, or constrained decoding in servers like vLLM): output is guaranteed to match the schema (syntax and types), though the content can still be wrong.

You'll measure the difference in Lab 1.

Which technique for which problem?

Need First choice Why Watch out
Change tone, format, task behavior Prompt engineering (+ few-shot examples) Cheapest, instant, reversible Prompt bloat, brittle to model changes
Answer from private or changing knowledge RAG Fresh data, citations, access control at retrieval time Retrieval quality is the bottleneck
Take actions / get live data Tools (function calling, MCP) Real-time, auditable Security and reliability (Ch 3, 10)
Consistent style/format at scale, cheaper smaller model, domain vocabulary Fine-tuning (LoRA, or InstructLab-style skill/knowledge tuning) Behavior baked in, shorter prompts Needs data, evals, retraining; poor for frequently changing facts
Fundamentally new capability Different/larger model Cost

Rule of thumb: prompt → RAG/tools → fine-tune. Fine-tuning teaches behavior; RAG supplies knowledge. Most enterprise "our model must know our data" requests are RAG problems.

Architect's lens

  • Ask "does the knowledge change?" (yes → RAG) and "is it a behavior/format problem?" (yes → prompt/fine-tune).
  • Combining is normal: RAG + tools + a lightly tuned small model.

Lesson 1.4: Economics: tokens, caching, and why agents multiply cost

Pricing model

  • Billed per input and output token, usually per million. Output tokens cost several times more than input.
  • Prompt (prefix) caching: repeated identical prefixes (system prompt, tool definitions, documents) can be billed at a discount and processed faster. Provider-specific rules apply; structure prompts with stable content first.
  • Batch APIs: asynchronous processing at a discount for non-urgent work.
  • Reasoning/thinking tokens count as output on most providers.
  • Self-hosted: you pay for GPUs and ops rather than tokens. Cost per token falls with utilization (Chapter 13).

Why agents multiply cost

An agent calls the model in a loop, and each call re-sends the whole growing context (system prompt + tools + history + tool results).

Worked example. System prompt + tool definitions = 2,000 tokens. Each step adds ~1,000 tokens (model output + tool result). Ten steps:

Step Input tokens sent
1 2,000
2 3,000
… …
10 11,000
Total input billed 65,000

The final context is only 11k tokens, yet you paid for ~65k of input, ~6× more, and that's before output and reasoning tokens. Add 3 retries or a multi-agent setup and it multiplies again.

Levers: prompt caching, shorter tool outputs, context compaction/summarization, fewer/better tools, smaller models for easy steps, step limits, budget caps per run.

Architect's lens

  • Quote costs per completed task, not per token, and include the loop multiplier.
  • Set budgets and step limits in every agent design (Chapter 2).
  • "Free" local models cost hardware, electricity and ops. Compare honestly (TCO in Chapter 13).

Step 3: The script

Save as compare.py. It streams every response, so it can measure time-to-first-token (TTFT) separately from decode speed, then tests structured output two ways.

"""Lab 1: compare a local and a hosted model through ONE OpenAI-compatible client.

Measures per model: time-to-first-token, total latency, decode speed (tokens/s),
token counts, and cost. Then tests structured-output reliability
(prompt-only JSON vs. JSON-schema-constrained output).

Usage:  uv run compare.py
Config: see .env.example
"""
import csv
import os
import statistics
import time
from typing import Literal

from dotenv import load_dotenv
from openai import OpenAI
from pydantic import BaseModel, ConfigDict, ValidationError

load_dotenv()

TEMP = os.environ.get("TEMPERATURE", "0")  # set to "" to omit (some reasoning models reject it)


def load_profile(prefix: str):
    """Build a model profile from env vars, or None if not configured."""
    base_url = os.environ.get(f"{prefix}_BASE_URL")
    if not base_url:
        return None
    return {
        "name": prefix.lower(),
        "base_url": base_url,
        "api_key": os.environ.get(f"{prefix}_API_KEY", "not-needed"),
        "model": os.environ[f"{prefix}_MODEL"],
        "price_in": float(os.environ.get(f"{prefix}_PRICE_IN", "0")),    # USD per 1M input tokens
        "price_out": float(os.environ.get(f"{prefix}_PRICE_OUT", "0")),  # USD per 1M output tokens
    }


PROFILES = [p for p in (load_profile("LOCAL"), load_profile("HOSTED")) if p]

PROMPTS = [
    "In two sentences, explain what a context window is.",
    "What is 17% of 2,340? Show the calculation briefly.",
    "Summarize the difference between TCP and UDP in three bullet points.",
    "Write a Python function that returns the n-th Fibonacci number iteratively.",
    "List three risks of giving an LLM direct write access to a production database.",
    "Translate to Italian: 'The deployment failed because the certificate expired.'",
    "A train leaves at 09:40 and arrives at 13:15. How long is the journey?",
    "Explain Kubernetes namespaces to a finance manager in under 60 words.",
    "Give one advantage and one disadvantage of RAG compared to fine-tuning.",
    "Rewrite politely: 'Your report is late again and it is full of mistakes.'",
]


def timed_chat(client, model, messages, **extra):
    """Streaming chat call. Returns text, ttft, latency, and token usage."""
    kwargs = dict(model=model, messages=messages, stream=True, **extra)
    if TEMP != "":
        kwargs["temperature"] = float(TEMP)

    def run(with_usage: bool):
        k = dict(kwargs)
        if with_usage:
            k["stream_options"] = {"include_usage": True}
        start = time.perf_counter()
        first, parts, usage = None, [], None
        for chunk in client.chat.completions.create(**k):
            if getattr(chunk, "usage", None):
                usage = chunk.usage
            if chunk.choices and chunk.choices[0].delta.content:
                if first is None:
                    first = time.perf_counter()
                parts.append(chunk.choices[0].delta.content)
        end = time.perf_counter()
        return "".join(parts), start, first, end, usage

    try:
        text, start, first, end, usage = run(with_usage=True)
    except Exception:  # some servers reject stream_options; retry without
        text, start, first, end, usage = run(with_usage=False)

    prompt_chars = sum(len(m["content"]) for m in messages)
    return {
        "text": text,
        "ttft": (first or end) - start,
        "latency": end - start,
        "in_tok": usage.prompt_tokens if usage else max(1, prompt_chars // 4),
        "out_tok": usage.completion_tokens if usage else max(1, len(text) // 4),
        "usage_reported": usage is not None,
    }


# ---------- Part A: latency / throughput / cost ----------
def benchmark(profile, client):
    rows = []
    for i, prompt in enumerate(PROMPTS):
        r = timed_chat(client, profile["model"], [{"role": "user", "content": prompt}])
        decode_time = max(r["latency"] - r["ttft"], 1e-6)
        cost = (r["in_tok"] * profile["price_in"] + r["out_tok"] * profile["price_out"]) / 1e6
        rows.append({
            "profile": profile["name"], "prompt": i, "ttft_s": round(r["ttft"], 3),
            "latency_s": round(r["latency"], 3), "in_tok": r["in_tok"], "out_tok": r["out_tok"],
            "tok_per_s": round(r["out_tok"] / decode_time, 1), "cost_usd": cost,
            "usage_reported": r["usage_reported"],
        })
        print(f"  [{profile['name']}] prompt {i}: {r['latency']:.2f}s, {r['out_tok']} out tokens")
    return rows


# ---------- Part B: structured output reliability ----------
class Ticket(BaseModel):
    model_config = ConfigDict(extra="forbid")  # -> additionalProperties:false (needed by strict mode)
    category: Literal["billing", "technical", "account", "other"]
    priority: Literal["low", "medium", "high"]
    summary: str


TICKETS = [
    "I was charged twice for my subscription this month, please fix ASAP!",
    "The VPN drops every 10 minutes since the last update. Very annoying.",
    "I can't reset my password, the email never arrives.",
    "Do you have a dark mode planned for the mobile app? Just curious.",
    "Production API is returning 500 errors for all customers right now!!",
]
SYSTEM_JSON = (
    "You triage support tickets. Reply with ONLY a JSON object with keys "
    "category (billing|technical|account|other), priority (low|medium|high), summary (string)."
)


def structured_test(profile, client, n=10):
    results = {}
    for mode in ("prompt_only", "json_schema"):
        ok = 0
        for i in range(n):
            msgs = [{"role": "system", "content": SYSTEM_JSON},
                    {"role": "user", "content": TICKETS[i % len(TICKETS)]}]
            extra = {}
            if mode == "json_schema":
                extra["response_format"] = {
                    "type": "json_schema",
                    "json_schema": {"name": "ticket", "schema": Ticket.model_json_schema(), "strict": True},
                }
            try:
                r = timed_chat(client, profile["model"], msgs, **extra)
                Ticket.model_validate_json(r["text"])  # strict: raw text must be valid JSON
                ok += 1
            except (ValidationError, ValueError):
                pass
            except Exception as e:  # e.g. provider doesn't support json_schema
                print(f"  [{profile['name']}] {mode} error: {type(e).__name__}: {str(e)[:120]}")
                break
        results[mode] = f"{ok}/{n}"
    return results


def summarize(rows):
    def med(key):
        return statistics.median(r[key] for r in rows)
    return {
        "median_ttft_s": round(med("ttft_s"), 2),
        "median_latency_s": round(med("latency_s"), 2),
        "median_tok_per_s": round(med("tok_per_s"), 1),
        "avg_out_tok": round(statistics.mean(r["out_tok"] for r in rows), 0),
        "cost_per_1k_req_usd": round(sum(r["cost_usd"] for r in rows) / len(rows) * 1000, 2),
    }


def main():
    if not PROFILES:
        raise SystemExit("No profiles configured. Copy .env.example to .env and fill it in.")
    all_rows, report = [], {}
    for p in PROFILES:
        print(f"\n== {p['name']} ({p['model']} @ {p['base_url']})")
        client = OpenAI(base_url=p["base_url"], api_key=p["api_key"], timeout=180)
        rows = benchmark(p, client)
        all_rows += rows
        report[p["name"]] = {**summarize(rows), **{f"struct_{k}": v for k, v in structured_test(p, client).items()}}

    with open("results.csv", "w", newline="") as f:
        w = csv.DictWriter(f, fieldnames=list(all_rows[0].keys()))
        w.writeheader()
        w.writerows(all_rows)

    metrics = list(next(iter(report.values())).keys())
    print("\n| metric | " + " | ".join(report) + " |")
    print("|---|" + "---|" * len(report))
    for m in metrics:
        print(f"| {m} | " + " | ".join(str(report[k][m]) for k in report) + " |")
    print("\nRaw data saved to results.csv")


if __name__ == "__main__":
    main()
